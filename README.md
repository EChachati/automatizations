# Automatizations

Reproducible setup for a CachyOS + Hyprland + Noctalia machine: dotfiles,
the exact package list, and the scripts for the machine-specific bits.

One repo, one command. On a fresh install:

```bash
git clone <this-repo> ~/Projects/automatizations
cd ~/Projects/automatizations
./bootstrap.sh
```

`bootstrap.sh` checks the system, replays `packages/*.list`, links the
dotfiles, then runs the machine detection. Use `./bootstrap.sh --dry-run`
first to see everything it would do without touching the machine.

## Layout

| Path | What it holds |
|------|---------------|
| `bootstrap.sh` | Entry point. Runs packages → dotfiles → machine setup. |
| `launch.sh` | Menu over every script, if you prefer picking step by step. |
| `packages/` | The exact package set (see below). |
| `dotfiles/` | Files symlinked straight into `$HOME`. Mirrors the home layout. |
| `ktemplated/` | Files that need your paths or git identity substituted. |
| `scripts/` | One script per concern, plus `scripts/lib/` helpers. |
| `docker/` | Compose configs used by `install-infra.sh`. |

## Packages

Two files, both generated by `scripts/snapshot-packages.sh`:

| File | Purpose |
|------|---------|
| `pacman-explicit.list` | Repository packages to install. |
| `aur-explicit.list` | AUR / foreign packages. |

Installs are replayed by name, deliberately. Arch is a rolling release, so
pinning versions would fight the distribution and rot on its own; the repo
tracks the current package set and lets the mirrors supply current versions.
What you get is the same *set* of software, not the same builds.

If you ever need an older build, that comes from the pacman cache rather
than from this repo:

```bash
sudo pacman -U /var/cache/pacman/pkg/<package>-<oldversion>.pkg.tar.zst
```

Keep that cache around with `paccache -r` and a retention policy, otherwise
the versions you might want are the ones already gone.

After installing or removing software, refresh the snapshot so the repo
keeps describing the machine you actually have:

```bash
./scripts/snapshot-packages.sh
```

## Dotfiles

`dotfiles/` mirrors your home directory, so `dotfiles/.config/hypr` becomes
`~/.config/hypr`. Each top-level entry becomes a symlink; directories that
need to hold a templated file are descended into instead of being linked
wholesale, which keeps `~/.config` a real directory.

Anything with a hardcoded path or personal identity lives in
`ktemplated/` instead. Those files are rendered into
`~/.cache/automatizations/rendered/` and symlinked from there, so they can
be regenerated without touching the repo.

| Placeholder | Resolves to |
|-------------|-------------|
| `@HOME@` | Your home directory |
| `@USER@` | Your username |
| `@HOSTNAME@` | `hostname` |
| `@GIT_NAME@` | `git config user.name` |
| `@GIT_EMAIL@` | `git config user.email` |

`install-dotfiles.sh` backs up anything it finds in the way into
`~/.config-backup-<timestamp>/` rather than deleting it, and it is
idempotent, so re-running is safe.

```bash
./scripts/install-dotfiles.sh --dry-run   # preview
./scripts/install-dotfiles.sh --target /tmp/test   # try without touching $HOME
./scripts/install-dotfiles.sh --force     # overwrite instead of backing up
```

### Secrets

`~/.config/fish/conf.d/secrets.fish` is where private exports go. It is
gitignored and never overwritten, so set it up once per machine.

## Machine-specific setup

Displays, GPU, bootloader, snapshots and power cannot be captured as
files, because they depend on the hardware. `scripts/install-machine.sh`
detects them instead of hardcoding them.

The display mapping is the part worth understanding. Connector names like
`DP-1` or `HDMI-A-2` differ per machine, so they are not in the dotfiles.
The script asks `hyprctl` which outputs are connected and writes
`~/.config/hypr/config/machine.lua`, which `config/variables.lua` picks up
through a `require`. If that file is missing, the config falls back to
single-display defaults and says so on startup.

**Run it with every monitor plugged in.** A connector that is not connected
cannot be detected, and the script warns when it had to guess.

```bash
./scripts/install-machine.sh                    # everything
./scripts/install-machine.sh --only monitors    # just the display mapping
hyprctl reload                                  # apply without restarting
```

## Scripts

| Script | Description |
|--------|-------------|
| `bootstrap.sh` | Packages, then dotfiles, then machine setup. |
| `install-packages.sh` | Replays `packages/*.list`. `--dry-run` lists without installing. |
| `install-dotfiles.sh` | Links `dotfiles/`, renders `ktemplated/`. |
| `install-machine.sh` | Displays, hostname, GPU, bootloader, snapper, power. |
| `snapshot-packages.sh` | Re-captures the installed package set. |
| `install-dev-tools.sh` | Editors, Python toolchain, cloud CLIs, Claude Code. |
| `install-git-ssh-connections.sh` | SSH keys for GitHub (one or two accounts) and GitLab. |
| `install-vpn-pritunl.sh` | Pritunl client plus `.ovpn` profiles from `~/vpn/`. |
| `install-postgres.sh` | Native PostgreSQL: install, init, `development` db, Docker access. |
| `install-infra.sh` | MinIO, Redis, MongoDB, LocalStack on the `app-network` network. |

All of them accept `--dry-run` and `-h`/`--help`. `install-machine.sh`
also takes `--only <topics>` and `--target <dir>` (`install-dotfiles.sh`
takes `--target` too), which is handy for testing without a real machine.

## Deliberately not versioned

These are either state, credentials, or data that each machine regenerates.
They are excluded on purpose, not by accident:

- **Application state and caches** — `discord/`, `zen/`, `VSCodium/`,
  `obsidian/`, `opencode/`, `dconf/`, micro's `buffers/`.
- **Credentials** — `fish/conf.d/secrets.fish`, `.ssh/`, `.pki/`, Proton
  profiles, `.ovpn` files.
- **Torrent client data** — `transmission/`, which holds a DHT cache and an
  RPC password. Reconfigure it through the GUI.
- **Package-manager state** — `.cargo/`, `.rustup/`, `.npm/`, `.steam/`, `.nv/`.
- **Wallpapers and media** — see below.

### Wallpapers

`config.toml` points at `~/Pictures/wallpapers` and the fastfetch logo lives
in `~/Pictures/fastfetch`. Those directories are not in the repo because
they hold images. `ktemplated/` renders the paths, so move the files across
and the config picks them up. The lockscreen hook
(`~/.config/noctalia/lockscreen-wallpaper.sh`) expects that folder to exist.

### Colours

`~/.config/hypr/noctalia.lua` and the terminal themes under
`kitty/themes/`, `alacritty/themes/` and `foot/themes/` are written by
Noctalia when it syncs your wallpaper. They are versioned so the repo
carries a working colour scheme, but changing the wallpaper regenerates
them and git will show the diff. Nothing to do about it, just do not
commit those changes unless you mean to.

## Environment variables

Set on first run by the scripts and appended to the config of whichever
shell is active. Persisted in shell-agnostic form: `set -gx NAME "value"`
for fish, `export NAME="value"` for bash and zsh.

```bash
export LOCALSTACK_AUTH_TOKEN="..."
export GITHUB_TOKEN="..."
export GOOGLE_APPLICATION_CREDENTIALS="~/.config/gcloud/application_default_credentials.json"
```
